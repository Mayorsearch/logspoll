# Cloudflare deployment preparation

**Deployment blocker:** Next.js/OpenNext build and Wrangler dry-run succeed, but local Worker preview returns HTTP 500: `Unexpected loadManifest(/.next/server/preview-props.json) call!`. OpenNext 1.20.10 does not include this Next.js 16.4 manifest in its inlined manifest loader. Do not deploy this bundle. Resolve with a maintained adapter fix or a separately verified compatible Next.js version, then repeat Worker runtime/auth checks. No framework downgrade or generated-bundle patch was applied.

LOGSPOLL uses Next.js server rendering, cookie sessions, route handlers, Proxy and Server Actions. Use **Cloudflare Workers with OpenNext**, not a static Pages folder upload. Workers provides a `workers.dev` address; this full-stack configuration does not produce a `pages.dev` website. No framework switch or static export is required.

- Build: `npm run build:cloudflare`. Entry: `.open-next/worker.js`; assets: `.open-next/assets`. Deploy both together through OpenNext/Wrangler after approval; uploading only the assets loses authentication and server actions.
- Local Worker preview after building: `npm run preview:cloudflare`. The ignored `.dev.vars` contains local Supabase publishable configuration; `.dev.vars.example` documents the variable names. No live deployment command was run.
- Before the eventual production build, set `NEXT_PUBLIC_SITE_URL` to the exact HTTPS Worker/custom-domain origin in the build environment. Set `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` in the Worker's runtime environment too. Keep staging and production Supabase projects separate. Never configure `LOGSPOLL_LOCAL_PANEL_TEST`, privileged Supabase keys or test-helper endpoints on Workers.
- In Supabase Auth → URL Configuration, set Site URL to that exact HTTPS origin and allow `/auth/callback` plus `/auth/callback?next=/account?mode=reset` for it. Keep the exact local origin allowed while testing. The supplied email templates use Site URL; set it to the environment being tested. Do not use broad wildcard callback hosts.
- In Cloudflare Workers Builds, use `npm run build:cloudflare` as build command. After approval, the deployment command is `npx opennextjs-cloudflare deploy`; there is no Pages output-directory setting. Do not enable automatic deployments before completing staging checks.
- Routing is handled by the Next.js Worker. Do not add an SPA fallback or rewrite all routes to `index.html`. Private pages must keep cookie forwarding and `private, no-store` responses; never enable Cache Everything on authenticated routes. Static assets have separate caching; Cloudflare Images binding is configured for Next.js image optimization.
- `wrangler.jsonc` enables Node compatibility and declares assets/self-reference/images. No R2/ISR infrastructure is added because the account and catalog routes are dynamic. The deploy target/domain, Cloudflare account permissions and final HTTPS origin still require owner configuration.

Launch gates: apply all Supabase migrations, configure SMTP/redirects, invite and verify both real test accounts, test recovery/session refresh/roles against hosted Supabase, populate authorized inventory and verify reviews end to end. Checkout, payment verification and wallet funding remain disabled. Do not enable payments or deploy while these features are incomplete.

Sources: [Cloudflare Next.js/OpenNext guidance](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/), [OpenNext configuration](https://opennext.js.org/cloudflare/get-started).

Compatibility note: the installed OpenNext version builds Next.js 16 Proxy, but labels Node middleware support experimental. A successful build/dry run does not prove hosted authentication; complete real staging email, recovery and session-refresh checks before deployment. The production dependency audit is tracked in CHECKPOINT.md; four unresolved development-only advisory reports affect the existing ESLint/braces dependency chain (no patched braces release currently available). The Cloudflare tooling's glob command-injection advisory was patched without downgrading the framework.
